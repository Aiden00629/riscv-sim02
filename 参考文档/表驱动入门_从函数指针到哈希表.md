# 表驱动入门：从函数指针到哈希表

> 日期：2026-09-06 ｜ 定位：**语法与概念的补课文档**，看不懂 `OpFunc table[128]` 这种写法时翻这里。
> 配套：《表驱动改造实战_riscv-sim版.md》讲怎么改我们的项目；本文只讲"这些语法什么意思"。
> 前置：会写 C++ 的函数、数组、switch 即可。

---

## 〇、一句话概括

> **表驱动 = 把「逻辑」变成「数据」，代码只负责「查表照做」。**

对比：

```cpp
// if-else / switch：流程写死在代码里，加一条就要改流程
switch (op) {
case '+': return a + b;
case '-': return a - b;
}

// 表驱动：流程固定不动，加一条 = 往表里加一行数据
return table[op](a, b);
```

代码不再"知道"有哪些运算，它只知道"去表里找"。**表里有什么，程序就能做什么。**

---

## 一、第一块砖：函数指针

### 1.1 变量能装什么

你早就知道变量能装数字、能装地址：

```cpp
int   x = 42;       // 装一个整数
int*  p = &x;       // 装一个「整数的地址」
```

**新知识：变量也能装「函数的地址」。**

```cpp
int fadd(int a, int b) { return a + b; }   // 一个普通函数

int (*p)(int, int);    // 声明：p 是一个能装这类函数的变量
p = fadd;              // 装进去（函数名不带括号 = 它的地址）
p(3, 5);               // 调用，效果 == fadd(3, 5)，得 8
```

### 1.2 `int (*p)(int, int)` 怎么读

拆成三块看：

```
int        (*p)      (int, int)
↑返回类型   ↑指针名   ↑参数表
```

读作：**「p 是一个指针，指向『吃两个 int、返回一个 int』的函数」**。

对照记忆：

| 写法 | 含义 | 变量里装的是 |
|---|---|---|
| `int x` | 整数变量 | 一个数 |
| `int* p` | 整数指针 | 一个数的**地址** |
| `int (*p)(int,int)` | 函数指针 | 一个函数的**地址** |

> 括号 `(*p)` 不能省。写成 `int *p(int,int)` 意思完全变了（那是"返回 int* 的函数声明"）。

### 1.3 你已经用过它了

Qt 里天天写的这行：

```cpp
connect(runTimer, &QTimer::timeout, this, &MainWindow::onTimerTick);
//                                        ↑ 这就是函数指针
```

`connect` 干的事就是：把 `onTimerTick` **存进一张「信号 → 函数」的表**，以后 `timeout` 信号来了就查表调用。

**Qt 的信号槽机制本身就是表驱动。** 你用了两个月，只是没意识到。

## 二、给类型起小名：typedef / using

`int (*)(int, int)` 每次都写太长，起个小名：

```cpp
typedef int (*OpFunc)(int, int);        // 老写法
using   OpFunc = int (*)(int, int);     // 新写法（C++11，和上面等价）
```

结构是 `typedef 【原类型】 【小名】;`。这跟你们 `common.h` 里的是同一件事：

```cpp
using u32 = unsigned int;    // 给 unsigned int 起小名叫 u32
```

起完之后，`OpFunc` 就是个**正常类型名**，像 `int` 一样用：

```cpp
OpFunc f = fadd;      // 声明一个函数指针变量
OpFunc arr[128];      // 声明一个函数指针数组 ← 这就是"表"
```

> 💡 **看不懂复杂类型时的通用技巧**：先假装它是 `int`，把结构看明白，再换回来。
> `OpFunc table[128]` 难懂？先看 `int table[128]`——哦，是个 128 格的数组。那前者就是"128 格的数组，每格装函数地址"。

## 三、第一种表：数组表（键是数字）

### 3.1 完整可运行示范

```cpp
#include <cstdio>

// ① 把 switch 里每个 case 的逻辑，拎成独立函数
int fadd(int a, int b) { return a + b; }
int fsub(int a, int b) { return a - b; }
int fmul(int a, int b) { return a * b; }
int fdiv(int a, int b) { return a / b; }

// ② 给函数指针类型起小名
typedef int (*OpFunc)(int, int);

// ③ 建表：128 格，先全填空
OpFunc table[128] = {nullptr};

// ④ 查表：从 20 行 switch 缩成 4 行
int calc(char op, int a, int b) {
    OpFunc f = table[(unsigned char)op];   // 打开第 op 号格子
    if (f == nullptr) return 0;            // 空格 = 原来的 default
    return f(a, b);                        // 有货 = 调用它
}

int main() {
    // ⑤ 登记：把「运算符 → 函数」的对子放进表
    table['+'] = fadd;
    table['-'] = fsub;
    table['*'] = fmul;
    table['/'] = fdiv;

    printf("%d\n", calc('+', 3, 5));   // 8
    printf("%d\n", calc('*', 4, 7));   // 28
    printf("%d\n", calc('?', 1, 2));   // 0（没登记过）
    return 0;
}
```

编译跑（Qt 自带的 g++）：

```bash
/e/qt/Tools/mingw1310_64/bin/g++.exe table_demo.cpp -o table_demo.exe && ./table_demo.exe
```

### 3.2 储物柜类比

把表想成 **128 格的储物柜**，格子编号 0~127，每格能放一张纸条写着"去找 fadd"。

| 代码 | 储物柜里发生了什么 |
|---|---|
| `OpFunc table[128] = {nullptr};` | 造 128 个格子，全空 |
| `table['+'] = fadd;` | `'+'` 的 ASCII 是 43 → **往 43 号格子塞"去找 fadd"的纸条** |
| `OpFunc f = table[op];` | 打开第 op 号格子，把纸条拿出来 |
| `f(a, b)` | 照纸条上写的，把 fadd 叫来干活 |

### 3.3 为什么 `table['+']` 能当下标

**字符在内存里本来就是数字**（ASCII 码）：

| 字符 | ASCII |
|---|---|
| `'+'` | 43 |
| `'-'` | 45 |
| `'*'` | 42 |
| `'/'` | 47 |
| `'A'` | 65 |
| `'a'` | 97 |

所以 `table['+']` 编译器看到的就是 `table[43]`。开 128 格是因为 ASCII 一共 128 个。

> `(unsigned char)op` 是保险：`char` 在有些编译器上是有符号的，遇到 ASCII > 127 的字符会变成负数，负下标会越界崩溃。转成 `unsigned char` 保证落在 0~127。

### 3.4 表的两个生命阶段

| 阶段 | 干什么 | 对应代码 |
|---|---|---|
| **登记**（一次性，程序启动时） | 往格子里放东西 = **填数据** | `table['+'] = fadd;` |
| **查询**（运行时，无数次） | 取出来照做 = **查表** | `table[op](a, b)` |

**核心价值**：加新运算只动"登记"（数据），永远不动 `calc`（流程）。

## 四、第二种表：键值表（键是字符串）

### 4.1 为什么需要它

数组下标**只能是整数**。但我们的指令名是 `"addi"`、`"lw"` 这种**字符串**，塞不进方括号：

```cpp
table["addi"] = ...;   // ✗ 数组做不到
```

解决方案：换一种容器——`unordered_map`（哈希表）。

### 4.2 完整示范

```cpp
#include <cstdio>
#include <string>
#include <unordered_map>

int fadd(int a, int b) { return a + b; }
int fmul(int a, int b) { return a * b; }

typedef int (*OpFunc)(int, int);

// 键是 string、值是 OpFunc 的表
std::unordered_map<std::string, OpFunc> table;

int calc(const std::string& op, int a, int b) {
    auto it = table.find(op);          // 查：找不到返回 table.end()
    if (it == table.end()) return 0;   // 没登记过
    return it->second(a, b);           // ->second 是「值」，调用它
}

int main() {
    table["add"] = fadd;               // 登记：直接拿字符串当键
    table["mul"] = fmul;

    printf("%d\n", calc("mul", 7, 8)); // 56
    printf("%d\n", calc("pow", 2, 3)); // 0
    return 0;
}
```

对比一下登记那行，和数组表**形状完全一样**，只是键从字符变成了字符串：

```cpp
table['+']   = fadd;    // 数组表：单引号，字符
table["add"] = fadd;    // 键值表：双引号，字符串
```

### 4.3 `find()` 和 `->second` 语法解释

这是键值表唯一比数组表多的语法负担：

```cpp
auto it = table.find(op);
```

- `find()` 返回一个**迭代器**（iterator），可以理解成"指向表里某一条记录的指针"
- 找不到时，返回特殊值 `table.end()`（表尾标记 = "查无此项"）
- `auto` 让编译器自己推断类型（那个类型名写全了很长，不值得手写）

```cpp
it->second
```

表里每条记录是一个**键值对**（pair）：

| 成员 | 含义 | 本例中是 |
|---|---|---|
| `it->first` | 键 | `"mul"` |
| `it->second` | 值 | `fmul` 函数指针 |

所以 `it->second(a, b)` = 拿出值（函数指针）→ 调用它。

> **偷懒写法**（有坑，知道就行）：`table[op](a,b)` 也能查，但 `operator[]` 遇到不存在的键会**自动插入一条空记录**，然后你调用空指针 → 崩溃。所以查询统一用 `find()`，登记才用 `[]`。

## 五、哈希表内部：为什么字符串能当键

### 5.1 秘密：内部还是数组

`unordered_map` 偷偷做了"字符串 → 数字"的换算：

```
"add" → 哈希函数 → 某个数字（比如 97+100+100 = 297）→ 数组第 297 格
```

这个换算函数叫**哈希函数**（hash function）。`unordered` 的意思就是"元素顺序按哈希值排，不是你插入的顺序"。

### 5.2 哈希冲突：必然发生

不同的键可能算出同一个数字：

```
"add" → 97 + 100 + 100 = 297
"dda" → 100 + 100 + 97 = 297   ← 撞了
```

**这不可避免**——键有无穷种，格子数量有限（鸽巢原理）。

### 5.3 解法：每格挂一条链，且连键带值一起存

```
格子 297 → [("add", fadd)] → [("dda", fdda)] → 空
            ↑ 键值成对存        ↑ 撞一起的挂后面
```

查 `"add"` 的三步：

1. 算哈希 → 297 → 定位到 297 号格子
2. 沿链表逐个**比较键**：`"add" == "add"` ✓
3. 返回对应的值

### 5.4 ⭐ 一句话记住哈希表

> **哈希值只负责「缩小范围」，最终判定永远靠比较键本身。**

- 哈希值相同 ≠ 同一个键（还得比键）
- 哈希值不同 → 一定不同 → 看都不用看

这也解释了为什么表里必须**连键带值一起存**：光存值的话，撞在同一格的两条记录就分不清谁是谁。

### 5.5 冲突的代价与退化

| 情况 | 查找耗时 | 相当于 |
|---|---|---|
| 散得开（正常） | 一步到位 O(1) | 直接开抽屉 |
| 全撞一格（最坏） | n 次 O(n) | **退化成链表，和 if-else 链一样慢** |

> 💡 **重要洞见**：`if (m=="addi") else if (m=="andi") ...` 这种 if-else 链，
> **本质上就是一个退化的哈希表**——25 条指令排成一串，查最后一条要走 25 步。
> 表驱动不只是"好维护"，也确实更快。

真正的 `unordered_map` 还带自动保护：某条链太长时会**扩容 + 重算全部哈希**（叫 rehash），把长链打散。这些它全包了，你不用管。

### 5.6 对我们项目的影响：零担心

指令名只有 25~37 个，散在几百上千格里，冲突极少。`unordered_map` 把哈希、拉链、扩容全做完了，你只管写 `table["addi"] = {...}`。

## 六、两种表怎么选

| | 数组表 | 键值表 |
|---|---|---|
| 写法 | `OpFunc table[128]` | `unordered_map<string, T>` |
| 键的类型 | 只能整数（0 ~ N-1） | 任意（字符串、结构体…） |
| 速度 | 最快（直接算地址） | 很快（多一次哈希） |
| 内存 | 固定 N 格，可能浪费 | 按需增长 |
| 查不到怎么判 | `== nullptr` | `== table.end()` |
| **我们项目用在** | **CPU 执行**（键 = opcode，本来就是 0~127 的数字） | **汇编器**（键 = `"addi"` 字符串） |

**选择口诀**：键本来就是小范围整数 → 数组表；键是字符串或范围很大 → 键值表。

## 七、常见错误速查

| 错误写法 | 问题 | 正确写法 |
|---|---|---|
| `table['+'] = fadd();` | **带括号 = 调用函数**，把返回值赋给了表 | `table['+'] = fadd;` |
| `int *p(int,int);` | 这是"返回 int* 的函数声明"，不是函数指针 | `int (*p)(int,int);` |
| `table[op](a,b)` 查 map | 键不存在时会插入空记录 → 调空指针崩溃 | 用 `find()` 先判 `end()` |
| 忘了登记就查 | 数组表读到 `nullptr` → 崩溃 | 查询前判空，或登记兜底函数 |
| 函数签名不一致 | 表里的函数必须**参数和返回值完全相同** | 统一签名，多余信息用参数传 |
| `table[op]` 下标越界 | `char` 可能是负数 | `table[(unsigned char)op]` |

## 八、自检题

不写代码，能答上来就算过关：

1. `OpFunc p = fsub;` 之后，`p(10, 4)` 得几？
2. `table['/'] = fdiv;` 执行后，第 47 号格子里装的是什么？
3. 没登记过 `'-'` 时，`calc('-', 9, 5)` 返回几？
4. 如果哈希函数永远返回 0（所有键都撞一格），哈希表退化成什么？查一个键最坏要比几次？
5. 为什么哈希表里必须连"键"一起存，只存值不行？

<details>
<summary>答案</summary>

1. **6**。`p` 装的是 fsub 的地址，`p(10,4)` == `fsub(10,4)` == 10-4。
2. **fdiv 这个函数的地址**（不是函数本身，是"去哪找它"的地址）。
3. **0**。第 45 号格子是 `nullptr`，`calc` 里判空返回 0。
4. **退化成链表**，最坏要比 **n 次**（n = 表里的元素个数）。这也正是 if-else 链的性能。
5. 因为**不同的键会撞进同一格**。只存值的话，297 号格子里的 fadd 和 fdda 分不清哪个属于 "add"、哪个属于 "dda"。**哈希定格子，比键定真身。**

</details>
